DevOps Toolbox

One command turns a fresh Linux server into a ready DevOps workstation. You get modern CLI tools, Kubernetes and cloud CLIs, alias packs, a themed banner pinned at the top of the screen, and one-command k3s clusters. This guide shows how to use every part, with copy-paste examples.

01 · START HERE

Overview

Every new server usually means the same half hour: download tools, write aliases, fix the prompt, set up kubeconfig. The toolbox does all of it from a public GitHub repo, uthrapathy-m/devops-toolbox. An interactive menu lets you pick exactly what goes on each box.

Installer

One command per server

curl … | bash opens a menu with 6 profiles and 42 items. Re-running it is safe: anything already installed is skipped.

Workspace

Pinned banner + tmux

A themed DEVOPS banner with live stats stays at the top. Your SSH session survives disconnects.

Kubernetes

Clusters in one line

Plain k3d and k3s commands give you a cluster in one line. k9s and sofka come themed, with plugins.

The repo has three scripts. Each runs in a different place:

ScriptRun it onWhat it does
install-devops-tool.shEach Linux serverMenu-driven installer for tools, aliases, dotfiles, the banner and clusters
install-fonts.ps1Your Windows PCInstalls Cascadia + JetBrains Mono Nerd Fonts and can set the Windows Terminal font
install-fonts.shYour macOS / Linux desktopSame fonts for macOS and Linux desktops; refuses to run on a headless server
02 · START HERE

How it fits together

Your computer draws the text. The server runs the tools. That's why fonts are installed on your PC, and everything else goes on the server.

Key idea

Run install-fonts on the machine you SSH from. Fonts installed on a server never change how your terminal looks, so install-fonts.sh stops with an explanation when it detects a headless SSH session.

With sudo, tools go to /usr/local/bin and the package manager handles tmux, htop, ncdu and docker. Without sudo, static binaries go to ~/.local/bin, and package-only tools are reported as skipped.

Bashinstaller examples

curl -fsSL $URL | bash                                   # menus
curl -fsSL $URL | bash -s -- -p k8s                      # K8s Ops pre-ticked, still adjustable
curl -fsSL $URL | bash -s -- -p k8s -y --theme matrix    # no questions
curl -fsSL $URL | bash -s -- -t fzf,btop,zoxide,alias-git -y
curl -sfL https://get.k3s.io | sh -s - --disable traefik  # real k3s server (k3s itself)
curl -fsSL $URL | bash -s -- -p everything -y --upgrade  # update everything
curl -fsSL $URL | bash -s -- --list                      # all item ids
Rate limit

Most tools come from their latest GitHub release, and GitHub allows 60 unauthenticated API calls per hour per IP. If several servers install at the same time from one NAT, run export GITHUB_TOKEN=… first.

Why tmux

Your work survives disconnects

If Wi-Fi drops, your commands keep running. SSH back in and you're exactly where you were.

Safe

Never locks you out

Only the first shell of an SSH login attaches, never nested shells or VS Code terminals. If tmux fails, you get a normal shell.

Keys (prefix Ctrl-a)

KeysAction
Ctrl-a bHide / show the pinned banner in this window
Ctrl-a zZoom the current pane to full screen (again to restore)

Ctrl-a | / -Split side by side / top and bottom

Bashbanner controls
toolbox-pin off        # remove the pinned banner everywhere (remembered)
toolbox-pin on         # bring it back in every window
toolbox-banner         # print the full banner once

# turn off auto-tmux on SSH, keep everything else
echo 'export DEVOPS_TOOLBOX_TMUX=0' >> ~/.devops-toolbox/custom.sh

# login banner style: 1 = toolbox banner, fastfetch, 0 = off
echo 'export DEVOPS_TOOLBOX_BANNER=fastfetch' >> ~/.devops-toolbox/custom.sh

The pinned pane is skipped on windows smaller than 26 rows or 60 columns. In that case the full banner prints once at login instead.

Example: debug a crashing pod in under a minute

Textinside k9s

Shift-0                 # pods view

sofka is a newer Kubernetes UI written in Rust. sofka import k9s converts your k9s plugins and hotkeys for it, and :skin previews its skins. The toolbox manages only a marked skin block in ~/.config/sofka/config.toml; the rest of the file is yours.

08 · HANDS-ON

k3s & k3d clusters

k3d · in K8s Ops

Test clusters in Docker

Multi-node on one machine, created in about 20 seconds and deleted just as fast. Needs Docker.

k3s server · opt-in

A real cluster

Runs as a systemd service and survives reboots. Other machines can join as workers. Needs sudo.

Bashk3d · test clusters in Docker
k3d cluster create dev --agents 2      # 1 server + 2 workers in Docker
k3d cluster list                       # what's running
k3d node list                          # the containers behind each node
k3d cluster stop dev                   # pause it (start dev to resume)
k3d cluster delete dev                 # remove it
Bashk3s · a real server on this machine
curl -sfL https://get.k3s.io | sh -s - --disable traefik   # drop the flag to keep Traefik
sudo systemctl status k3s              # running as a service
sudo k3s kubectl get nodes             # works straight away, as root

# use it as your normal user (kubectl, k9s, sofka)
mkdir -p ~/.kube
sudo cp /etc/rancher/k3s/k3s.yaml ~/.kube/config   # overwrites: back up an existing config first
sudo chown "$USER": ~/.kube/config && chmod 600 ~/.kube/config
k get nodes

/usr/local/bin/k3s-uninstall.sh        # remove k3s completely

k3d adds each cluster to ~/.kube/config by itself as the context k3d-<name>. For k3s you copy /etc/rancher/k3s/k3s.yaml once, as above. After that k get nodes, k9s and sofka work without sudo. Switch between clusters with kctx.

Add worker machines

StepWhereCommand
J1ServerInstall k3s (above), then sudo cat /var/lib/rancher/k3s/server/node-token
J2AWS console / CLISecurity group: allow TCP 6443, UDP 8472, TCP 10250 from the same group
J3Each workercurl -sfL https://get.k3s.io | K3S_URL=https://<server-private-ip>:6443 K3S_TOKEN=<token> sh -
J4Serverk get nodes: every worker shows Ready
BashJ2 · open the ports (AWS CLI)
SG=sg-0123456789abcdef0     # the group all nodes share
aws ec2 authorize-security-group-ingress --group-id $SG --ip-permissions \
  "IpProtocol=tcp,FromPort=6443,ToPort=6443,UserIdGroupPairs=[{GroupId=$SG}]" \
  "IpProtocol=udp,FromPort=8472,ToPort=8472,UserIdGroupPairs=[{GroupId=$SG}]" \
  "IpProtocol=tcp,FromPort=10250,ToPort=10250,UserIdGroupPairs=[{GroupId=$SG}]"
Watch out

The join token works like a cluster password. Read it from /var/lib/rancher/k3s/server/node-token only when you need it, don't paste it into tickets or chat, and clear it from your shell history (history -d) after a join.

Example workflows

A · A fresh EC2 instance ready in five minutes

Bashnew Ubuntu instance
ssh -i ~/.ssh/my-key.pem ubuntu@<ip>
curl -fsSL https://raw.githubusercontent.com/uthrapathy-m/devops-toolbox/main/install-devops-tool.sh | bash -s -- -p k8s -y
exit                                   # log out once (docker group + tmux)
ssh -i ~/.ssh/my-key.pem ubuntu@<ip>   # lands in tmux with the pinned banner
k3d cluster create dev --agents 2      # a 3-node cluster to play with
k get nodes && k9

B · Set up servers automatically at launch (user data)

BashEC2 user data / cloud-init
#!/bin/bash
# runs as root at first boot; installs for the ubuntu user, no menus
sudo -u ubuntu -H bash -c 'curl -fsSL https://raw.githubusercontent.com/uthrapathy-m/devops-toolbox/main/install-devops-tool.sh | bash -s -- -p core -y --theme amber'

C · A three-node k3s cluster on AWS

Bashserver + 2 workers
# on the server
curl -fsSL $URL | bash -s -- -t kubectl,k9s,alias-k8s,dot-k8s-tui -y   # tools only
curl -sfL https://get.k3s.io | sh -s - --disable traefik
sudo cat /var/lib/rancher/k3s/server/node-token                     # copy the token
hostname -I | awk '{print $1}'                                      # server private IP

# on each worker (same security group, ports from section 08 open)
curl -sfL https://get.k3s.io | K3S_URL=https://10.0.1.15:6443 K3S_TOKEN='K10…::server:…' sh -

# back on the server (after copying k3s.yaml to ~/.kube/config, section 08)
k get nodes -o wide                    # 3 nodes, all Ready

Bashone theme per environment
# -i loads the toolbox in a non-tty shell (no tmux attach); output hidden

Bashmaintain
curl -fsSL $URL | bash                          # add items (installed ones are skipped)
curl -fsSL $URL | bash -s -- -p everything -y --upgrade   # update to latest releases
/usr/local/bin/k3s-uninstall.sh                 # remove k3s first, if you installed it
curl -fsSL $URL | bash -s -- --uninstall        # remove toolbox config + its binaries

Uninstall keeps packages installed with apt/dnf (tmux, htop, docker) and keeps k3s, which is a system service. Remove those separately if you want them gone.
